# ask_user 等待回答时显示问号状态

## 目标
多个会话并行时，用户能通过标题状态指示快速定位正在等待自己回答的会话，避免将其误认为仍在执行。

## 已确认事实
- SessionProjection 已有 pendingAsks，ask-request/ask-resolved 维护其生命周期。
- src/shared/conversationDotTone.ts 已支持 waiting，优先于 running，但 failed 仍优先。
- Sidebar.tsx 的 ConversationDot 与 ChatView.tsx 的 StatusDot 目前将 waiting 渲染成闪烁绿点。
- CoworkerTabs.tsx 将提问与审批统一渲染为红色 attention 点；主会话标签目前没有独立状态点。
- 用户所述蓝点现象尚不能仅凭源码确认原因，实施时须核对具体显示入口与状态传递，不以替换颜色作为已修复依据。

## 范围与要求
- 桌面侧边栏会话标题、聊天区状态指示、coworker 标签的 ask_user 等待态使用一致的琥珀色问号图标，不闪烁。
- 悬停提示及可访问名称表达“等待你回答”，跟随项目中英文国际化。
- 以真实待回答请求为依据，而非仅判断工具名；问题挂起期间持续展示。
- 回答、取消、超时或停止导致 pendingAsks 清空后，恢复真实会话状态；多个问题须全部解除后退出问号态。
- 非提问状态的运行蓝点、失败红点、未读标识及审批行为保持不变。共享 failed 优先级保持不变。
- 各指示器保留原所在位置，不为主会话标签新增重复状态点。

## 不在范围
- 手机端状态协议与 UI。
- 新通知、自动切换会话、会话排序、父会话聚合子会话提问状态。
- 改动 ask_user 工具、超时策略或审批流程。

## 验收
1. running 会话产生待回答提问后，相关桌面指示器由圆点变为琥珀色问号，非当前会话也可辨认。
2. 提问解决且继续运行时恢复蓝点；多问题场景仍有挂起问题时保持问号。
3. 取消、超时、停止后无过期问号残留。
4. 非提问状态不回归，正常审批仍按原语义显示。
5. 检查状态传递入口；可单测逻辑改动严格 Red-Green；运行 typecheck、test、相关 Biome 检查，并通过 Electron CDP 验证显示与恢复。
6. 不覆盖现有其他任务工作区修改；如共享文件并发变化，保留彼此修改。
