# 会话右键菜单增加重新读取会话

## 目标
用户发现前端显示与后端实际会话内容不同步时，能够手动重新读取指定会话，恢复权威内容。

## 已确认背景
- 会话侧栏菜单位于 `src/renderer/components/chat/Sidebar.tsx`；子会话标签也有右键菜单，位于 `src/renderer/components/chat/CoworkerTabs.tsx`。
- renderer 使用会话正文缓存，已有 worker snapshot 请求入口（`src/renderer/stores/sessions/index.ts:79-86`）。
- 已结束子会话的读取存在正文非空/已尝试即跳过的限制（`src/renderer/stores/sessions/index.ts:509-536`），手动重读不能仅复用该缓存命中行为。

## 要求
- 会话右键菜单提供“重新读取会话”，作用于右键选中的会话；子会话标签菜单保持一致。
- 明确重新向后端读取权威内容，不因前端已有正文或曾读取过而跳过。
- 不重启或中断代理，不发送用户消息，不改写后端历史，不清除输入草稿。
- 支持运行中的会话以及有历史的已结束会话；未产生后端历史的空白会话禁用入口。
- 读取失败时保留原有内容并反馈错误；重复操作及读取期间的事件不得导致内容重复或旧数据覆盖新数据。

## 验收标准
1. 主会话及子会话菜单能找到“重新读取会话”。
2. 有缓存时点击仍触发后端读取，成功后展示权威消息和关联时间线内容。
3. 已结束子会话曾加载过仍可以再次读取。
4. 运行中的代理继续运行，草稿不丢失；失败不清空现有内容。
5. 新增可单测逻辑按 TDD 验证，类型检查、测试、格式检查通过，并验证实际菜单行为。

## 范围外
不增加自动轮询同步、不刷新整个应用、不改变会话存储格式、不扩展手机或远程节点菜单。

## 风险
需在实现前进一步核查 snapshot 与增量事件的排序契约，以及未启动历史会话的读取路径，避免以恢复代理执行来代替只读刷新。
